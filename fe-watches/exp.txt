# Các tính năng tìm kiếm và lọc
## Stores
- Tìm kiếm theo: 
  + Tên cửa hàng: `?search=keyword` (tìm trong `name`, `address`, `phone`)
  + Mã cửa hàng: `?search=keyword` (tìm trong `store_code`)
- Lọc theo: 
  + Trạng thái: `?is_active=true`
  + Quản lý: `?manager=1`
- Sắp xếp theo: 
  + Tên: `?ordering=name` hoặc `?ordering=-name`
  + Thời gian tạo: `?ordering=created_at` hoặc `?ordering=-created_at`
- Phân trang: Mặc định 10 items/trang
- API list_all: Lấy tất cả cửa hàng không phân trang
- API đếm nhân viên: `/api/stores/stores/{id}/employee_count/`

## Employees
- Tìm kiếm theo: 
  + Tên nhân viên: `?search=keyword` (tìm trong `name`, `phone`, `employee_code`)
  + Email: `?search=keyword` (tìm trong `email`)
- Lọc theo: 
  + Cửa hàng: `?store=1`
  + Vị trí: `?position=Quản lý`
  + Quản lý: `?is_manager=true`
  + Ngày thuê: `?hire_date_from=2024-01-01&hire_date_to=2024-12-31`
- Sắp xếp theo: 
  + Tên: `?ordering=name` hoặc `?ordering=-name`
  + Ngày thuê: `?ordering=hire_date` hoặc `?ordering=-hire_date`
  + Thời gian tạo: `?ordering=created_at` hoặc `?ordering=-created_at`
- Phân trang: Mặc định 10 items/trang
- API list_all: Lấy tất cả nhân viên không phân trang

## Suppliers
- Tìm kiếm theo: 
  + Tên nhà cung cấp: `?search=keyword` (tìm trong `name`, `contact_person`, `email`, `phone`)
  + Mã số thuế: `?search=keyword` (tìm trong `tax_code`)
- Lọc theo: 
  + Trạng thái: `?is_active=true`
- Sắp xếp theo: 
  + Tên: `?ordering=name` hoặc `?ordering=-name`
  + Thời gian tạo: `?ordering=created_at` hoặc `?ordering=-created_at`
- Phân trang: Mặc định 10 items/trang
- API list_all: Lấy tất cả nhà cung cấp không phân trang

```json
    "updated_at": "2024-12-19T10:30:00Z"

```

**Các trường bắt buộc:**
- `purchase_order`: ID của đơn đặt hàng (integer)
- `product_variant`: ID của biến thể sản phẩm (integer)
- `quantity`: Số lượng đặt hàng (integer > 0)
- `unit_price`: Đơn giá (decimal >= 0)

**Các trường tùy chọn:**
- `discount_percent`: Phần trăm giảm giá (decimal 0-100, mặc định 0)
- `tax_percent`: Phần trăm thuế (decimal 0-100, mặc định 0)
- `notes`: Ghi chú (string)
- `expected_delivery_date`: Ngày giao hàng dự kiến (datetime)

**Validation Rules:**
- `quantity` phải lớn hơn 0
- `unit_price` không được âm
- `discount_percent` phải từ 0 đến 100
- `tax_percent` phải từ 0 đến 100
- `purchase_order` và `product_variant` phải tồn tại
- Không được trùng lặp `purchase_order` + `product_variant`

**Tự động tính toán:**
- `discount_amount`: Số tiền giảm giá = (quantity × unit_price × discount_percent) / 100
- `subtotal`: Thành tiền = (quantity × unit_price) - discount_amount
- `tax_amount`: Số tiền thuế = subtotal × tax_percent / 100
- `total_amount`: Tổng tiền = subtotal + tax_amount

**Lưu ý:**
- Khi tạo chi tiết đơn hàng, hệ thống sẽ tự động cập nhật tổng tiền của đơn đặt hàng
- Không thể tạo chi tiết cho đơn đặt hàng đã hoàn thành hoặc đã hủy
- Mỗi sản phẩm chỉ có thể xuất hiện một lần trong đơn đặt hàng

- `draft` - Nháp (mới tạo)
- `pending` - Chờ xác nhận
- `confirmed` - Đã xác nhận (đã cập nhật tồn kho)
- `completed` - Hoàn thành
- `cancelled` - Đã hủy

**Quy trình làm việc:**

1. **Tạo phiếu nhập kho** → Trạng thái `draft`
   - Có thể tạo từ đơn đặt hàng hoặc tạo thủ công
   - Chi tiết phiếu nhập có số lượng mặc định 0

2. **Cập nhật số lượng nhập** → API `update_received_quantities`
   - Nhập `received_quantity`, `accepted_quantity`, `rejected_quantity`
   - Tự động tính lại `subtotal`, `tax_amount`, `discount_amount`
   - Cập nhật `quality_status` dựa trên số lượng

3. **Xác nhận phiếu nhập kho** → API `confirm_receipt`
   - Chuyển trạng thái sang `confirmed`
   - **TỰ ĐỘNG** cập nhật tồn kho cho tất cả sản phẩm có `accepted_quantity > 0`
   - Tạo `InventoryTransaction` để ghi lại lịch sử
   - Cập nhật `received_quantity` trong `PurchaseOrderDetail`
   - Cập nhật trạng thái `PurchaseOrder`

4. **Hoàn thành phiếu nhập** → API `update_inventory`
   - Chuyển trạng thái sang `completed`
   - Ghi nhận `actual_delivery_date`

**Lưu ý quan trọng:**
- Tồn kho chỉ được cập nhật **một lần** khi xác nhận phiếu nhập kho
- Nếu hủy xác nhận (chuyển từ `confirmed` về trạng thái khác), tồn kho sẽ được **trừ lại**
- Chỉ số lượng `accepted_quantity` mới được cộng vào tồn kho
- Mỗi sản phẩm chỉ được cập nhật tồn kho **một lần** cho mỗi phiếu nhập kho

- `is_quality_checked`: Boolean (true nếu quality_status khác 'pending')
- `can_update_inventory`: Boolean (true nếu accepted_quantity > 0 và quality_status là 'accepted' hoặc 'partial')

# Các tính năng tìm kiếm và lọc cho Purchases
## Purchase Orders
- Tìm kiếm theo: 
  + Mã đơn đặt hàng: `?search=keyword` (tìm trong `po_number`)
  + Nhà cung cấp: `?search=keyword` (tìm trong `supplier__name`, `supplier__email`)
  + Cửa hàng: `?search=keyword` (tìm trong `store__name`)
  + Nhân viên: `?search=keyword` (tìm trong `employee__name`, `employee__email`)
  + Ghi chú: `?search=keyword` (tìm trong `notes`)
- Lọc theo: 
  + Nhà cung cấp: `?supplier=1`
  + Cửa hàng: `?store=1`
  + Nhân viên: `?employee=1`
  + Trạng thái: `?status=ordered`
  + Trạng thái thanh toán: `?payment_status=pending`
  + Ngày đặt hàng: `?order_date_from=2024-12-01&order_date_to=2024-12-31`
  + Ngày giao hàng dự kiến: `?expected_delivery_date_from=2024-12-01&expected_delivery_date_to=2024-12-31`
  + Tổng tiền: `?total_amount_min=1000000&total_amount_max=10000000`
- Sắp xếp theo: 
  + Mã đơn hàng: `?ordering=po_number` hoặc `?ordering=-po_number`
  + Ngày đặt hàng: `?ordering=order_date` hoặc `?ordering=-order_date`
  + Tổng tiền: `?ordering=total_amount` hoặc `?ordering=-total_amount`
  + Thời gian tạo: `?ordering=created_at` hoặc `?ordering=-created_at`
- Phân trang: Mặc định 10 items/trang

## Goods Receipts
- Tìm kiếm theo: 
  + Mã phiếu nhập: `?search=keyword` (tìm trong `receipt_number`)
  + Nhà cung cấp: `?search=keyword` (tìm trong `supplier__name`, `supplier__email`)
  + Cửa hàng: `?search=keyword` (tìm trong `store__name`)
  + Nhân viên: `?search=keyword` (tìm trong `employee__name`, `employee__email`)
  + Số phiếu giao hàng: `?search=keyword` (tìm trong `delivery_note`)
  + Ghi chú: `?search=keyword` (tìm trong `notes`)
- Lọc theo: 
  + Đơn đặt hàng: `?purchase_order=1`
  + Nhà cung cấp: `?supplier=1`
  + Cửa hàng: `?store=1`
  + Nhân viên: `?employee=1`
  + Trạng thái: `?status=confirmed`
  + Ngày nhập kho: `?receipt_date_from=2024-12-01&receipt_date_to=2024-12-31`
  + Kiểm tra chất lượng: `?is_quality_checked=true`
  + Tổng tiền: `?total_amount_min=1000000&total_amount_max=10000000`
- Sắp xếp theo: 
  + Mã phiếu nhập: `?ordering=receipt_number` hoặc `?ordering=-receipt_number`
  + Ngày nhập kho: `?ordering=receipt_date` hoặc `?ordering=-receipt_date`
  + Tổng tiền: `?ordering=total_amount` hoặc `?ordering=-total_amount`
  + Thời gian tạo: `?ordering=created_at` hoặc `?ordering=-created_at`
- Phân trang: Mặc định 10 items/trang
- API đặc biệt:
  + `GET /get_available_purchase_orders/` - Lấy danh sách đơn đặt hàng có thể tạo phiếu nhập
  + `GET /get_purchase_order_info/?purchase_order=1` - Lấy thông tin đơn đặt hàng để tạo phiếu nhập
  + `POST /create_from_purchase_order/` - Tạo phiếu nhập kho từ đơn đặt hàng
  + `GET /{id}/get_receipt_details/` - Lấy chi tiết phiếu nhập với thông tin đơn đặt hàng
  + `GET /{id}/get_receipt_summary/` - Lấy thông tin tổng quan về phiếu nhập
  + `POST /{id}/update_received_quantities/` - Cập nhật số lượng nhập từ đơn đặt hàng
  + `POST /{id}/update_prices_from_purchase_order/` - Cập nhật thông tin giá từ đơn đặt hàng

## Goods Receipt Details
- Tìm kiếm theo: 
  + Mã phiếu nhập: `?search=keyword` (tìm trong `goods_receipt__receipt_number`)
  + Sản phẩm: `?search=keyword` (tìm trong `product_variant__name`, `product_variant__sku`)
  + Số lô: `?search=keyword` (tìm trong `batch_number`)
  + Ghi chú: `?search=keyword` (tìm trong `notes`, `quality_notes`)
- Lọc theo: 
  + Phiếu nhập kho: `?goods_receipt=1`
  + Sản phẩm: `?product_variant=1`

  + Kiểm tra chất lượng: `?is_quality_checked=true`

# Quyền truy cập cho Purchases
## Purchase Orders
- Cho phép user đã đăng nhập xem danh sách và chi tiết đơn đặt hàng (IsStoreEmployee)
- Yêu cầu quyền superuser cho các thao tác thêm/sửa/xóa (IsSuperUser)
- Người dùng thông thường chỉ có thể xem đơn đặt hàng của cửa hàng họ thuộc về
- Superuser có thể xem và quản lý tất cả đơn đặt hàng

## Goods Receipts
- Cho phép user đã đăng nhập xem danh sách và chi tiết phiếu nhập kho (IsStoreEmployee)
- Yêu cầu quyền superuser cho các thao tác thêm/sửa/xóa (IsSuperUser)
- Người dùng thông thường chỉ có thể xem phiếu nhập kho của cửa hàng họ thuộc về
- Superuser có thể xem và quản lý tất cả phiếu nhập kho

# Tính năng đặc biệt của Purchases
## Tự động tạo mã
- Purchase Order: Tự động tạo mã PO + YYYYMMDD + 4 số thứ tự (VD: PO202412190001)
- Goods Receipt: Tự động tạo mã GR + YYYYMMDD + 4 số thứ tự (VD: GR202412190001)

## Tự động tính toán
- Tự động tính tổng tiền cho đơn đặt hàng và phiếu nhập kho
- Tự động tính giảm giá và thuế cho từng chi tiết
- Tự động cập nhật số lượng đã nhận trong đơn đặt hàng
- Tự động điền thông tin supplier, store từ purchase_order khi tạo goods_receipt

## Liên kết với Inventory
- Khi xác nhận phiếu nhập kho, tự động cập nhật tồn kho
- Tạo InventoryTransaction để ghi lại lịch sử nhập kho
- Cập nhật số lượng đã nhận trong PurchaseOrderDetail

## Quản lý chất lượng
- Kiểm tra chất lượng hàng nhập (accepted/rejected/partial)
- Chỉ cập nhật tồn kho cho hàng được chấp nhận
- Ghi chú chất lượng cho từng sản phẩm
- Tính toán chênh lệch số lượng và tài chính giữa đơn đặt hàng và nhập kho

## Ràng buộc dữ liệu
- Mỗi đơn đặt hàng chỉ có thể tạo 1 phiếu nhập kho duy nhất
- Mỗi sản phẩm chỉ có thể xuất hiện một lần trong chi tiết phiếu nhập kho
- Validation trạng thái đơn đặt hàng trước khi cho phép nhập kho

## Tạo phiếu nhập từ đơn đặt hàng
- Tự động tạo chi tiết phiếu nhập từ tất cả chi tiết đơn đặt hàng
- Tự động điền thông tin supplier, store, expected_receipt_date từ đơn đặt hàng
- Kiểm tra và tránh tạo trùng lặp sản phẩm trong phiếu nhập kho
- Validation đơn đặt hàng chưa có phiếu nhập kho

## Cập nhật thông tin từ đơn đặt hàng
- Cập nhật số lượng nhập (received_quantity, accepted_quantity, rejected_quantity)
- Cập nhật thông tin giá (unit_price, discount_percent, tax_percent) từ đơn đặt hàng
- Tự động tính toán lại tổng tiền phiếu nhập kho
- Cập nhật số lượng đã nhận trong PurchaseOrderDetail

## Dashboard và báo cáo
- Thống kê tiến độ nhận hàng theo đơn đặt hàng
- Báo cáo nhập kho theo nhà cung cấp, cửa hàng, thời gian
- Tính toán chênh lệch số lượng và tài chính
- Tóm tắt vấn đề chất lượng hàng nhập
- Theo dõi thiệt hại do hàng kém chất lượng
- Thông tin tổng quan về phiếu nhập (số lượng, chất lượng, tài chính)

# Trạng thái chuyển kho và ý nghĩa
## pending
- Chuyển kho mới được tạo
- Có thể chỉnh sửa thông tin và chi tiết
- Chưa bắt đầu quá trình chuyển kho

## in_transit
- Chuyển kho đang được thực hiện
- Hàng đã được đóng gói và vận chuyển
- Có thể cập nhật số lượng đã nhận

## completed
- Chuyển kho đã hoàn thành
- Tất cả hàng đã được nhận
- Không thể chỉnh sửa thông tin

## cancelled
- Chuyển kho đã bị hủy
- Không thể khôi phục hoặc chỉnh sửa
- Có thể tạo chuyển kho mới thay thế

# Quy trình làm việc chuyển kho
1. **Tạo chuyển kho** → Trạng thái `pending`
   - Chọn cửa hàng nguồn và đích
   - Thêm chi tiết sản phẩm cần chuyển
   - Đặt ngày chuyển kho

2. **Bắt đầu chuyển kho** → Trạng thái `in_transit`
   - Xác nhận bắt đầu quá trình chuyển kho
   - Có thể cập nhật số lượng đã nhận

3. **Hoàn thành chuyển kho** → Trạng thái `completed`
   - Xác nhận tất cả hàng đã được nhận
   - Cập nhật tồn kho (nếu cần)

4. **Hủy chuyển kho** → Trạng thái `cancelled`
   - Hủy chuyển kho nếu cần thiết
   - Không thể khôi phục sau khi hủy

## 2.1 Stock Transfer Logic (Đã hoàn thiện)

### API Endpoints:
```
POST /api/inventory/stock-transfers/{id}/confirm_transfer/ - Xác nhận chuyển kho
POST /api/inventory/stock-transfers/{id}/cancel_transfer/ - Hủy chuyển kho
POST /api/inventory/stock-transfers/{id}/start_transfer/ - Bắt đầu chuyển kho

GET /api/inventory/stock-transfers/statistics/ - Thống kê tổng quan
```

### Logic tự động:
```python
# Khi confirm transfer:
1. Kiểm tra tồn kho nguồn
2. Trừ tồn kho nguồn + tạo transaction OUT
3. Cộng tồn kho đích + tạo transaction IN
4. Cập nhật trạng thái thành 'completed'

# Khi cancel transfer:
1. Hoàn trả tồn kho nguồn + tạo transaction IN
2. Trừ lại tồn kho đích + tạo transaction OUT
3. Cập nhật trạng thái thành 'cancelled'
```

## 2.2 Stock Take Logic (Đã hoàn thiện)

### API Endpoints:
```
POST /api/inventory/stock-takes/{id}/complete_stock_take/ - Hoàn thành kiểm kê
POST /api/inventory/stock-takes/{id}/cancel_stock_take/ - Hủy kiểm kê
POST /api/inventory/stock-takes/{id}/update_stock_take_details/ - Cập nhật chi tiết
GET /api/inventory/stock-takes/{id}/summary/ - Thống kê kiểm kê
GET /api/inventory/stock-takes/statistics/ - Thống kê tổng quan
```

### Logic tự động:
```python
# Khi complete stock take:
1. So sánh expected vs actual quantity
2. Điều chỉnh inventory theo actual quantity
3. Tạo transaction cho chênh lệch
4. Cập nhật trạng thái thành 'completed'

# Khi cancel stock take:
1. Hoàn trả inventory về expected quantity
2. Tạo transaction hoàn trả
3. Cập nhật trạng thái thành 'cancelled'
```

## 2.3 Order Logic (Đã hoàn thiện)

### Logic tự động:
```python
# Khi tạo order với status 'deducted':
1. Kiểm tra tồn kho
2. Trừ tồn kho + tạo transaction OUT
3. Lưu order với status tương ứng

# Khi cập nhật order status:
- Từ 'returned' sang 'deducted': Trừ tồn kho
- Từ 'deducted' sang 'returned': Hoàn trả tồn kho
- Tạo transaction tương ứng

# Khi xóa order:
1. Hoàn trả tồn kho nếu status là 'deducted'
2. Tạo transaction hoàn trả
3. Xóa mềm order
```

```python
3. Cập nhật trạng thái purchase order

# Khi cancel goods receipt:
1. Trừ lại tồn kho + tạo transaction OUT
2. Cập nhật trạng thái
```

- `out_of_stock_only` (optional): Chỉ lấy sản phẩm hết hàng (true/false)
- `ordering` (optional): Sắp xếp (mặc định: -last_updated)

```json
}
```

## 9.2 Ví dụ sử dụng API

### Lấy danh sách sản phẩm trong kho cửa hàng:
```bash
GET /api/inventory/store_inventory/?store_id=1&in_stock_only=true&ordering=-quantity
```

### Thống kê tồn kho cửa hàng:
```bash
GET /api/inventory/store_statistics/?store_id=1
```

### Tìm kiếm sản phẩm:
```bash
GET /api/inventory/product_search/?q=casio&store_id=1&limit=10
```

### Cảnh báo sắp hết hàng:
```bash
GET /api/inventory/low_stock_alert/?store_id=1&threshold=5
```

## 9.3 Tính năng nổi bật

### ✅ **Lọc và tìm kiếm thông minh**:
- Tìm kiếm theo tên sản phẩm, SKU, mô tả
- Lọc theo số lượng (min/max)
- Lọc theo trạng thái tồn kho (còn hàng/hết hàng)

### ✅ **Thống kê chi tiết**:
- Tổng quan tồn kho
- Thống kê theo danh mục, thương hiệu
- Top sản phẩm có số lượng cao nhất
- Sản phẩm sắp hết hàng

### ✅ **Cảnh báo thông minh**:
- Cảnh báo sản phẩm sắp hết hàng
- Cảnh báo sản phẩm hết hàng
- Ngưỡng cảnh báo có thể tùy chỉnh

### ✅ **Bảo mật và phân quyền**:
- Kiểm tra quyền truy cập theo cửa hàng
- Chỉ hiển thị dữ liệu cửa hàng được phép
- Validation dữ liệu đầu vào

Hệ thống quản lý tồn kho đã được hoàn thiện với đầy đủ tính năng cần thiết cho việc quản lý kho hàng theo cửa hàng!
